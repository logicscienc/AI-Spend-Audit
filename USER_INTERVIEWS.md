# USER_INTERVIEWS.md

## Interview 1

**Name:** Deepak Singh
**Role:** Freelance Frontend Developer
**Stage:** Individual freelancer / side projects

### Answers

**1. Which AI tools do you currently use most often?**
Mostly ChatGPT and GitHub Copilot. Sometimes I also try Cursor when working on bigger React projects.

**2. Are you personally paying for any AI subscriptions right now?**
Yes, I pay for ChatGPT Plus and Copilot.

**3. Have you ever felt you might be overpaying or paying for overlapping tools?**
Yeah honestly sometimes both tools do similar things and I probably don’t need both every month.

**4. If a tool showed you cheaper alternatives or downgrade suggestions, would you use it?**
Definitely. Especially if it clearly explained what I’d lose or keep after downgrading.

**5. What would make you trust a cost-saving recommendation tool?**
If the recommendations are transparent and show actual pricing comparisons instead of random AI suggestions.

### Most surprising thing

The user said they often forget about active subscriptions after project deadlines and continue paying without checking usage.

### What it changed in my design

I added clearer per-tool savings breakdowns and focused on making downgrade recommendations easy to understand.

## Interview 2

**Name:** Aastha Mishra
**Role:** Computer Science Student + Internship Projects
**Stage:** Student / early-stage developer

### Answers

**1. Which AI tools do you currently use most often?**
Mostly ChatGPT and Claude for coding help and assignments.

**2. Are you personally paying for any AI subscriptions right now?**
Right now only ChatGPT Plus.

**3. Have you ever felt you might be overpaying or paying for overlapping tools?**
Sometimes yes because free versions are already good enough for many tasks.

**4. If a tool showed you cheaper alternatives or downgrade suggestions, would you use it?**
Yes, especially if it saved money without affecting productivity too much.

**5. What would make you trust a cost-saving recommendation tool?**
Real pricing data and practical explanations instead of generic recommendations.

### Most surprising thing

The user cared more about understanding why a recommendation was made than the savings number itself.

### What it changed in my design

I improved the audit reasoning section so every recommendation includes a short explanation instead of only showing savings numbers.
